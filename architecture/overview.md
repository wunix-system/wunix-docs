# Общая архитектура Wunix

**Wunix** — это независимая UNIX-подобная операционная система, создаваемая с нуля на языке программирования Rust.

---

## 1. Цели и принципы проектирования

Проект ориентирован на создание современной, безопасной и расширяемой платформы общего назначения:

1. **Гарантия безопасности памяти (Memory Safety)**:
   - Использование Rust позволяет исключить на этапе компиляции типичные уязвимости C/C++: use-after-free, buffer overflows, data races и двойные освобождения.
   - Низкоуровневые блоки `unsafe` строго изолированы во внутренних слоях абстракции `arch/` и драйверах.
2. **Модульная архитектура ядра (Hybrid Modular Kernel)**:
   - Монолитная производительность с модульной изоляцией компонентов.
   - Драйверы и файловые системы взаимодействуют с ядром через четкие типизированные типажи (traits).
3. **UNIX-философия и POSIX-совместимость**:
   - «Все есть файл» (Everything is a file) через абстракции виртуальной файловой системы (VFS).
   - Четкое разделение ответственности утилит и конвейерная обработка данных.
4. **Собственная экосистема без тяжелого легаси**:
   - Отсутствие устаревших костылей совместимости 16/32-битных эпох. Ядро изначально работает исключительно в 64-битном режиме (x86_64 Long Mode).
5. **Встроенная мультиязычность**:
   - Поддержка локализации на уровне архитектуры ядра и пользовательского интерфейса.

## 2. Слои операционной системы

Архитектура системы Wunix разделена на 6 взаимосвязанных слоев:

```
┌────────────────────────────────────────────────────────┐
│             Пользовательские приложения                │
│                 (Wunix Applications)                   │
├────────────────────────────────────────────────────────┤
│             Графическая среда и UI SDK                 │
│              (Wunix Desktop & Wunix UI)                │
├────────────────────────────────────────────────────────┤
│           Базовая пользовательская среда               │
│                    (Wunix Base)                        │
├────────────────────────────────────────────────────────┤
│             Системный интерфейс и API                  │
│               (System Calls / POSIX)                   │
├────────────────────────────────────────────────────────┤
│                  Ядро операционной системы             │
│                    (Wunix Core)                        │
├────────────────────────────────────────────────────────┤
│               Аппаратное обеспечение                   │
│             (x86_64 CPU, RAM, MMIO, I/O)               │
└────────────────────────────────────────────────────────┘
```

### Назначение слоев:

| Слой | Описание |
|---|---|
| **Wunix Applications** | Пользовательский софт: текстовый редактор, веб-браузер, файловый менеджер, утилиты разработки, терминал. |
| **Wunix Desktop & UI** | Графическое окружение: оконный композитор, панель задач, шрифтовой рендерер и библиотека интерфейсных компонентов Wunix UI. |
| **Wunix Base** | Пользовательская среда (аналог GNU Userland): системная библиотека libc/wlibc, командный интерпретатор WSH (Wunix Shell), базовые утилиты (`ls`, `cat`, `grep`, `cp`). |
| **System API** | Интерфейс быстрых системных вызовов (`syscall` / `sysret`) с валидацией указателей на границе Ring 3 / Ring 0. |
| **Wunix Core** | Ядро ОС: планировщик процессов, виртуальная память (Paging), драйверы железа, VFS, синхронизация. |
| **Hardware** | Физическое или виртуализированное (QEMU/KVM) оборудование. |

## 3. Пакетная система Wunix

Для разделения системных компонентов и прикладного программного обеспечения в Wunix предусмотрены две специализированные утилиты управления пакетами:

### WSP (Wunix System Package)
- Предназначен исключительно для обслуживания базовой операционной системы.
- Управляет обновлениями ядра (`wunix-kernel`), системных библиотек и критических служб.
- Поддерживает атомарные транзакции и откат к стабильным точкам восстановления (System Rollback).

### WPM (Wunix Package Manager)
- Пользовательский менеджер пакетов (аналог `apt`, `pacman`, `cargo`).
- Установка, удаление и обновление прикладных программ и утилит из репозиториев Wunix.
- Изоляция зависимостей и цифровая подпись пакетов.

## 4. Модель релизов и ветки разработки

Проект использует четырехступенчатую схему релизов:

| Ветка | Назначение | Стабильность |
|---|---|---|
| `unstable` | Активная разработка новых подсистем и драйверов ядра. | Возможны сбои и экспериментальные API. |
| `testing` | Интеграционное тестирование и стабилизация перед релизом. | Высокая. |
| `stable` | Проверенные релизы для пользователей и разработчиков софта. | Стабильная, строгий контроль изменений. |
| `LTS` | Долгосрочная поддержка (Long Term Support). | Максимальная надежность и исправления безопасности. |
