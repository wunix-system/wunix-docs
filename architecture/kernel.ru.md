# Архитектура ядра Wunix Core

Ядро **Wunix Core** представляет собой гибридное модульное ядро для архитектуры `x86_64`, работающее в 64-битном Long Mode под управлением современного протокола загрузки **Limine**.

---

## 1. Схема адресного пространства (Higher-Half Model)

Ядро Wunix загружается в верхнюю половину 64-битного виртуального адресного пространства (Higher-Half). Это освобождает нижнюю половину памяти (`0x0000_0000_0000_0000` .. `0x0000_7FFF_FFFF_FFFF`) для будущих процессов пользовательского режима (Ring 3).

```
0xFFFF_FFFF_FFFF_FFFF ┌────────────────────────────────────────┐
                      │ Базовый код ядра (Limine Kernel Mapping) │
0xFFFF_FFFF_8000_0000 ├────────────────────────────────────────┤
                      │ Динамическая куча ядра (Kernel Heap)   │ (1+ MiB)
0xFFFF_9000_0000_0000 ├────────────────────────────────────────┤
                      │ Прямое отображение физ. памяти (HHDM)  │
                      │ (Higher-Half Direct Map)               │
0xFFFF_8000_0000_0000 ├────────────────────────────────────────┤
                      │ Недоступная зона (Non-canonical hole)  │
0x0000_7FFF_FFFF_FFFF ├────────────────────────────────────────┤
                      │ Пространство пользователя (User Space) │ (Будущие Ring 3 процессы)
0x0000_0000_0000_0000 └────────────────────────────────────────┘
```

## 2. Модульная организация исходного кода

В соответствии с правилами разработки ядра ([`AGENTS.md`](file:///home/valdis/my-os/AGENTS.md)), исходный код разделен на четко изолированные подсистемы:

```
wunix/kernel/src/
├── arch/x86_64/              # Низкоуровневый железо-зависимый код CPU
│   ├── gdt.rs                # GDT, TSS и аварийный стек IST0 (20 КБ) для Double Fault
│   ├── idt.rs                # Таблица векторов прерываний и обработчики исключений
│   ├── interrupts.rs         # Диспетчеризация аппаратных прерываний (IRQ)
│   ├── pic.rs                # Ремаппинг контроллера прерываний 8259 PIC (векторы 32..47)
│   ├── timer.rs              # Системный таймер PIT 8254 (100 Гц, ticks, uptime)
│   └── port.rs               # Безопасные обертки I/O портов (inb, outb)
├── drivers/                  # Драйверы периферийных устройств
│   ├── display.rs            # Вывод во фреймбуфер Limine
│   ├── font.rs               # Растровый знакогенератор 8×16 (ASCII + Cyrillic)
│   ├── serial.rs             # COM1 UART 16550 для отладки
│   └── keyboard.rs           # PS/2 контроллер, кольцевой буфер и переключение раскладок
├── memory/                   # Подсистема управления памятью
│   ├── frame.rs              # Физический аллокатор 4 КиБ фреймов по карте памяти Limine
│   ├── paging.rs             # Управление 4-уровневыми таблицами страниц и трансляция
│   └── heap.rs               # Динамическая куча ядра (`alloc`, `linked_list_allocator`)
├── task/                     # Подсистема многозадачности (в разработке)
│   ├── context.rs            # Контекст регистров процессора
│   └── scheduler.rs          # Планировщик потоков ядра
├── i18n/                     # Подсистема локализации (kernel/src/i18n)
│   └── mod.rs                # Хранилище языка, MsgKey, tr(), t(), cmdline-парсер
├── lib.rs                    # Инициализация всех подсистем ядра (kernel_init)
└── main.rs                   # Точка входа ядра (_start) и обработка паник
```

## 3. Подсистема управления памятью

Память инициализируется в три этапа:

1. **HHDM и трансляция страниц (`memory/paging.rs`)**:
   Загрузчик Limine предоставляет смещение HHDM (`hhdm_request`), с помощью которого ядро получает прямой доступ к любому физическому адресу через виртуальное смещение.
2. **Физический аллокатор фреймов (`memory/frame.rs`)**:
   Парсит карту памяти `memmap_request` от Limine, отбирает доступные сегменты памяти (`LIMINE_MEMMAP_USABLE`) и выделяет свободные физ. страницы размером 4096 байт.
3. **Куча ядра (`memory/heap.rs`)**:
   Размещается по виртуальному адресу `0xFFFF_9000_0000_0000`. Начальный размер составляет 1 МиБ, активирует поддержку глобального аллокатора Rust и структур `Box`, `Vec`, `String` и `format!`.

---

## 4. Прерывания и аппаратный Bring-Up

1. **GDT и TSS (`arch/x86_64/gdt.rs`)**:
   Настраивает 64-битные сегменты кода и данных ядра. Выделяет выделенный стек исключения IST0 размером 20 КБ. При возникновении Double Fault (например, при переполнении стека) процессор аппаратно переключается на чистый стек IST0, предотвращая немедленный Triple Fault и перезагрузку.
2. **PIC 8259 (`arch/x86_64/pic.rs`)**:
   Базовые прерывания BIOS перемапливаются на диапазон векторов `32..47`, чтобы не пересекаться со стандартными процессорными исключениями Intel (`0..31`).
3. **IDT (`arch/x86_64/idt.rs`)**:
   Регистрирует безопасные Rust-обработчики исключений (Breakpoint, Page Fault, General Protection Fault) с дампом регистров CPU.

## 5. Графическая консоль и текстовый вывод

- Ядро запрашивает у Limine линейный графический фреймбуфер высокого разрешения (`FramebufferRequest`).
- В [`drivers/display.rs`](file:///home/valdis/my-os/wunix/kernel/src/drivers/display.rs) реализован консольный буфер с поддержкой:
  - скроллинга строк вверх при заполнении экрана;
  - управляющих символов `\n`, `\r`, `\t` и `\x08` (Backspace);
  - аппаратного курсора и очистки строк;
  - высококонтрастной цветовой палитры (белый текст на темном фоне).
- Все символы рисуются моноширинным растровым шрифтом 8×16 из [`drivers/font.rs`](file:///home/valdis/my-os/wunix/kernel/src/drivers/font.rs).
