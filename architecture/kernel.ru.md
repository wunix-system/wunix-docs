# Архитектура ядра Wunix Core

Ядро **Wunix Core** представляет собой гибридное модульное 64-битное ядро для процессорной архитектуры `x86_64`, разработанное с нуля на языке программирования Rust. Ядро работает в Long Mode под управлением загрузочного протокола **Limine**, изолирует пользовательские процессы в Ring 3 и поддерживает двойной интерфейс системных вызовов (Linux/POSIX и Windows NT ABI).

---

## 1. Схема виртуального адресного пространства (Higher-Half Model)

Ядро Wunix загружается исключительно в верхнюю половину 64-битного канонического адресного пространства (Higher-Half). Нижняя половина адресного пространства полностью изолирована и выделяется пользовательским процессам (Ring 3):

```
0xFFFF_FFFF_FFFF_FFFF ┌──────────────────────────────────────────┐
                      │ Базовый код ядра (Limine Kernel Mapping) │
0xFFFF_FFFF_8000_0000 ├──────────────────────────────────────────┤
                      │ Динамическая куча ядра (Kernel Heap)     │ (1+ МиБ, linked_list_allocator)
0xFFFF_9000_0000_0000 ├──────────────────────────────────────────┤
                      │ Прямое окно физической памяти (HHDM)     │
                      │ (Higher-Half Direct Map)                 │
0xFFFF_8000_0000_0000 ├──────────────────────────────────────────┤
                      │ Неканоническая дыра (Non-canonical hole) │
0x0000_7FFF_FFFF_FFFF ├──────────────────────────────────────────┤
                      │ Виртуальная библиотека vDSO / Syslib     │ (0x0000_7FFF_FFFF_0000)
                      ├──────────────────────────────────────────┤
                      │ Стек пользовательского процесса          │ (Растет вниз от 0x7FFF_... )
                      ├──────────────────────────────────────────┤
                      │ Динамическая память и проекции mmap      │
                      ├──────────────────────────────────────────┤
                      │ Сегменты кода и данных ELF / PE (Ring 3) │
0x0000_0000_0000_0000 └──────────────────────────────────────────┘
```

## 2. Модульная организация подсистем ядра

В строгом соответствии с архитектурным стандартом Single Responsibility Principle (SRP) кодовая база ядра разделена на изолированные подсистемы:

```

│   └── x86_64/
│       ├── cpu.rs                # Чтение регистров CR0..CR4, CPUID, MSR-регистры
│       ├── gdt.rs                # GDT, TSS и аварийный стек исключений IST0 (20 КиБ)
│       ├── interrupts.rs         # Таблица векторов IDT и обработчики CPU-исключений
│       ├── syscall.rs            # Низкоуровневый вход MSR LSTAR (инструкции syscall / sysretq)
│       └── timer.rs              # Системный таймер PIT 8254 (100 Гц) и счетчик uptime
├── drivers/                      # Подсистема оборудования и драйверов
│   ├── display.rs                # Вывод во фреймбуфер Limine с поддержкой ANSI escape-последовательностей
│   ├── font.rs                   # Растровый знакогенератор 8×16 (ASCII и кириллица)
│   ├── keyboard.rs               # Контроллер клавиатуры PS/2, кольцевой буфер и переключение RU/EN
│   ├── manager.rs                # Диспетчер оборудования DeviceManager и автоматический опрос устройств
│   ├── registry.rs               # Реестр обнаруженных драйверов ядра

│   ├── traits.rs                 # Унифицированные типажи: BlockDevice, NetDevice, CharDevice

│   └── virtio/                   # Драйверы стека VirtIO (blk, net, gpu, input, pci transport)

│   ├── ops.rs                    # Реализация операций VFS (open, read, write, stat, mkdir, unlink)
│   ├── path.rs                   # Трансляция путей C:\, нормализация слешей, case-insensitive поиск

│   ├── tar.rs                    # Парсер архивов POSIX ustar initramfs
│   ├── vfs.rs                    # Базовые трейты Inode, FileSystem, структуры Metadata и ошибки VfsError

│   ├── paging.rs                 # Трансляция 4-уровневых страниц (PML4, PDP, PD, PT) через HHDM

│   ├── scheduler.rs              # Планировщик потоков ядра (вытесняющий Round-Robin, квант 50 мс)

│   ├── syslib.rs                 # Виртуальная библиотека ядра vDSO (Syslib) по адресу 0x7FFF_FFFF_0000

│   ├── syscall/                  # Диспетчер системных вызовов Linux / POSIX (SRP-модули)
│   └── win_syscall/              # Диспетчер системных вызовов Windows NT ABI (SSN-диспетчер)
├── i18n/                         # Подсистема интернационализации (каталог MsgKey, tr!, t!)
├── version.rs                    # Информация о версии, коммите и сборке ОС
```

## 3. Подсистема управления памятью

Управление памятью строится на фундаменте смещения HHDM (Higher-Half Direct Map), предоставляемого загрузчиком Limine:

1. **Трансляция страниц (`memory/paging.rs`)**:
   - Ядро настраивает 4-уровневое страничное преобразование архитектуры x86_64: PML4 (Page Map Level 4) $\to$ PDPT $\to$ PD $\to$ PT.
   - Смещение HHDM позволяет коду ядра обращаться к любой физической странице по прямому виртуальному адресу: `virt = phys + hhdm_offset`.
2. **Аллокатор физических фреймов (`memory/frame.rs`)**:
   - Парсит карту памяти Limine (`memmap_request`), фильтрует доступные диапазоны оперативной памяти (`LIMINE_MEMMAP_USABLE`) и распределяет страницы размером 4096 байт.
3. **Куча ядра (`memory/heap.rs`)**:
   - Размещена в диапазоне адресов `0xFFFF_9000_0000_0000`. Начальный размер составляет 1 МиБ с возможностью динамического расширения.
   - Реализована на базе крейта `linked_list_allocator`, обеспечивающего поддержку стандартных структур Rust (`Box`, `Vec`, `String`, `BTreeMap`, форматирование через `format!`).
4. **Адресные пространства процессов (`memory/process.rs`, `vma.rs`)**:
   - Каждый процесс Ring 3 получает собственный каталог страниц PML4.
   - Верхняя половина адресного пространства ядра проецируется во все таблицы страниц процессов (Kernel Mapping), что исключает необходимость полной смены каталога CR3 при входе в сисколл.
   - Диапазоны пользовательской памяти управляются структурами VMA (Virtual Memory Area) с гранулярными правами доступа (чтение, запись, исполнение, `PROT_READ`, `PROT_WRITE`, `PROT_EXEC`).

## 4. Инициализация аппаратуры и прерывания (Bring-Up)

1. **GDT и сегмент TSS (`arch/x86_64/gdt.rs`)**:
   - Конфигурируются 64-битные дескрипторы сегментов: селекторы кода ядра (`0x08`), данных ядра (`0x10`), пользовательского кода Ring 3 (`0x1B` / `0x23`) и данных пользователя (`0x20`).
   - Настраивается сегмент состояния задачи TSS (Task State Segment) с выделением изолированного аварийного стека IST0 размером 20 КиБ. При возникновении аппаратного сбоя Double Fault процессор автоматически переключается на стек IST0, предотвращая немедленный сброс процессора в Triple Fault.
2. **Контроллер прерываний PIC 8259 (`arch/x86_64/interrupts.rs`)**:
   - Аппаратные прерывания BIOS переназначаются с векторов 8–15 на диапазон 32–47, исключая коллизии со встроенными процессорными исключениями Intel.
3. **Таблица векторов IDT (`arch/x86_64/interrupts.rs`)**:
   - Регистрируются обработчики процессорных исключений: Divide Error, Breakpoint, Double Fault, General Protection Fault (#GP), Page Fault (#PF) с детальным выводом регистрового контекста.
4. **Системный таймер PIT 8254 (`arch/x86_64/timer.rs`)**:
   - Конфигурируется на базовую частоту 100 Гц (квант времени 10 мс).
   - Прерывание IRQ0 инкрементирует атомарный счетчик системных тиков, обслуживает системный аптайм и инициирует квантование времени в планировщике задач.

## 5. Процессы, потоки и планировщик задач

Подсистема управления задачами (`task/`) реализует полноценную многозадачную среду пользовательского режима:

1. **Изоляция Ring 3**:
   - Пользовательский код исполняется с правами DPL=3, что аппаратно запрещает выполнение привилегированных инструкций (`cli`, `sti`, `in`, `out`, модификацию `CR3`) и прямой доступ к адресам ядра.
2. **Планировщик Round-Robin (`task/scheduler.rs`)**:
   - Вытесняющий планировщик распределяет процессорное время между потоками с фиксированным квантом 50 мс.
   - Потоки могут добровольно уступать управление через системный вызов `sys_yield` / `NtYieldExecution`.
3. **Переключение контекста (`task/context.rs`)**:
   - Ассемблерная процедура `context_switch` атомарно сохраняет регистры общего назначения x86_64 (`rsp`, `rbp`, `rbx`, `r12`..`r15`, `rflags`) текущего потока и восстанавливает состояние следующего выбранного потока.
4. **Загрузчики бинарников (`task/elf.rs`, `task/pe.rs`)**:
   - `elf.rs`: Разбирает заголовки 64-битного ELF (ELF64), проецирует сегменты `LOAD` в виртуальную память процесса и настраивает точку входа `e_entry`.
   - `pe.rs`: Обеспечивает прямую загрузку переносимых исполняемых файлов Windows PE32+ (Portable Executable), размечает секции `.text`, `.data`, `.rdata` и настраивает адрес начала исполнения.
5. **Поддержка локального хранилища потоков (TLS)**:
   - Через системный вызов `sys_arch_prctl` регистр `FS_BASE` процессора конфигурируется под базовый адрес TLS, что необходимо для многопоточных рантаймов Rust и C.

## 6. Диспетчер системных вызовов (Dual ABI)

В Wunix Core реализован гибридный шлюз системных вызовов через инструкцию x86_64 `syscall`:

- На этапе инициализации процессорный регистр MSR LSTAR программируется адресом ассемблерного трамплина `syscall_entry` ([`arch/x86_64/syscall.rs`](file:///home/valdis/my-os/wunix/kernel/src/arch/x86_64/syscall.rs)).
- Регистры MSR SFMASK и STAR задают автоматическое маскирование флагов процессора (сброс прерываний IF) и переход на селекторы Ring 0.
- **Разделение вызовов по сигнатурам и номерам**:
  - Если номер вызова соответствует системному вызову Linux (номера `0..334`), управление передается в модульный роутер `task/syscall/mod.rs`.
  - Если номер вызова соответствует соглашению Windows NT SSN (System Service Number, диапазон `0x0000`..`0x007F`), управление передается в диспетчер `task/win_syscall/mod.rs`.
- **Защита границ памяти**: Все указатели, поступающие из пользовательского пространства, проходят валидацию. Доступ к диапазону адресов выше `0x0000_7FFF_FFFF_FFFF` немедленно отклоняется с возвратом ошибки `-EFAULT`.

Подробный перечень реализованных системных вызовов приведен в документе [«Системные вызовы ядра Wunix»](syscalls.ru.md).

## 7. Виртуальная библиотека ядра vDSO (Syslib)

Для устранения накладных расходов на часто вызываемые функции и сисколлы в адресное пространство каждого Ring 3 процесса по виртуальному адресу `0x0000_7FFF_FFFF_0000` автоматически отображается read-only страница **vDSO / Syslib** ([`task/syslib.rs`](file:///home/valdis/my-os/wunix/kernel/src/task/syslib.rs)):

- **Метаданные `SyslibSharedInfo`**: Хранят сигнатуру `WUNIXLIB`, системную частоту таймера, время старта ядра и смещения экспортируемых функций.
- **Встроенные микрофункции**: Сверхбыстрые бессисколловые реализации `strlen`, `memcpy` (на базе ассемблерной инструкции `rep movsb`) и `memset` (`rep stosb`).
- **Быстрые трамплины**: Готовые ассемблерные шлюзы вызовов `read`, `write`, `getpid`, `close`, `exit`, оптимизирующие вызов сисколлов без ручной генерации инструкций `syscall`.

## 8. Подсистема драйверов и устройств VirtIO / PCI

Управление оборудованием централизовано в модуле [`drivers/manager.rs`](file:///home/valdis/my-os/wunix/kernel/src/drivers/manager.rs):

- **Шина PCI (`drivers/pci/`)**: При старте ядра сканирует все 256 шин, 32 слота и 8 функций PCI, определяет идентификаторы Vendor/Device ID, настраивает память MMIO и порты ввода-вывода BAR (Base Address Registers).
- **Стек VirtIO (`drivers/virtio/`)**:
  - `virtio-blk`: Драйвер постоянного блочного дискового накопителя. Обеспечивает синхронное и асинхронное чтение/запись 512-байтных секторов.
  - `virtio-net`: Драйвер гигабитного сетевого адаптера с кольцевыми буферами пакетов TX/RX.
  - `virtio-gpu`: Драйвер 2D/3D акселератора и виртуального видеоконтроллера.
  - `virtio-input`: Драйвер координатных манипуляторов и виртуальных клавиатур.

Подробное описание архитектуры драйверов представлено в документе [«Подсистема драйверов и устройств»](drivers.ru.md).

## 9. Сетевой стек

Сетевая подсистема ядра Wunix построена на интеграции чистого Rust-стека `smoltcp` с аппаратным драйвером `virtio-net`:

- **Сетевые интерфейсы**: Ядро регистрирует физический адаптер `eth0` и локальную петлю `lo`.
- **Поддержка протоколов**: Реализованы стеки Ethernet II, ARP, IPv4, ICMP (Echo Request / Echo Reply), UDP и TCP со скользящим окном.
- **Сокетный интерфейс VFS**: Сетевые сокеты представлены в VFS унифицированными дескрипторами `FileHandle::Socket`, что обеспечивает работу стандартного BSD-интерфейса: `socket`, `bind`, `listen`, `accept`, `connect`, `sendto`, `recvfrom`.

Подробное описание сетевого стека представлено в документе [«Сетевой стек Wunix»](network.ru.md).

## 10. Графический вывод и интернационализация (i18n)

- **Консольный вывод (`drivers/display.rs`)**: Линейный графический фреймбуфер Limine обслуживается высокопроизводительным драйвером с поддержкой вертикального скроллинга, управляющих символов (`\n`, `\r`, `\t`, Backspace) и парсинга цветов ANSI.
- **Растровый знакогенератор (`drivers/font.rs`)**: Моноширинный шрифт 8×16 пикселей содержит полный набор символов ASCII, расширенный латинский алфавит и кириллицу (CP866 / UTF-8).
- **Мультиязычность ядра (`i18n/mod.rs`)**: Сообщения ядра выводятся через макросы `tr!` и `t!` на основе системного словаря `MsgKey`. Язык задается параметром командной строки ядра (`lang=ru` или `lang=en`) либо переменной окружения.
