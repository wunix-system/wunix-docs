# Руководство разработчика: Сборка, запуск и отладка Wunix

Данный документ содержит инструкции по настройке окружения, компиляции ядра, запуску в эмуляторе QEMU и отладке операционной системы **Wunix**.

---

## 1. Системные требования и инструменты

Для разработки и сборки ядра Wunix требуются следующие утилиты:

- **Rust Nightly**: ядро использует нестабильные возможности языка (`build-std`, bare-metal target, ассемблерные вставки).
- **QEMU (`qemu-system-x86_64`)**: эмулятор целевой платформы x86_64.
- **xorriso**: утилита генерации гибридного загрузочного ISO-образа (BIOS + UEFI).
- **make & git**: для сборки хостовых утилит Limine.

### Установка зависимостей в Ubuntu / Debian:

```bash
sudo apt-get update
sudo apt-get install -y qemu-system-x86 xorriso make git build-essential
rustup toolchain install nightly
rustup default nightly
rustup component add rust-src --toolchain nightly
```

## 2. Сборка ядра

Исходный код ядра расположен в каталоге `wunix/kernel/`.

```bash
cd wunix/kernel

# Быстрая проверка типизации и синтаксиса:
cargo check

# Компиляция отладочного бинарного файла ядра:
cargo build
```

Скомпилированный бинарный файл ELF Higher-Half ядра создается по пути:
`wunix/kernel/target/x86_64-unknown-none/debug/wunix-kernel`.

## 3. Запуск через автоматический скрипт `tools/run.sh`

В каталоге `wunix/tools/` находится главный скрипт автоматизации `run.sh`. Он выполняет:
1. Автоматическую загрузку и сборку загрузчика Limine (если он еще не загружен).
2. Компиляцию ядра Rust.
3. Генерацию загрузочного каталога `iso_root` с правильным `limine.conf`.
4. Создание загрузочного гибридного ISO-образа `wunix.iso` через `xorriso`.
5. Запуск QEMU с передачей вывода COM1 в терминал.

### Базовый запуск:

```bash
# Запуск с русским языком (по умолчанию):
./tools/run.sh ru

# Запуск с английским языком:
./tools/run.sh en
```

### Параметры виртуализации QEMU:

Скрипт `run.sh` поддерживает настройку ресурсов виртуальной машины через переменные окружения:

| Переменная | По умолчанию | Примеры значений | Назначение |
|---|---|---|---|
| `QEMU_RAM` | `512M` | `256M`, `1G`, `2G` | Объем выделяемой оперативной памяти |
| `QEMU_SMP` | `1` | `2`, `4` | Количество виртуальных ядер процессора |
| `QEMU_CPU` | `qemu64` | `qemu64`, `max`, `host` | Модель виртуального CPU |
| `ENABLE_KVM` | `0` | `1` | Аппаратная виртуализация KVM (требует `/dev/kvm`) |
| `WUNIX_LANG` | `ru` | `ru`, `en`, `de` | Язык системных сообщений ядра |

#### Примеры расширенного запуска:

```bash
# Запуск с 2 ГБ ОЗУ и 4 ядрами процессора:
QEMU_RAM=2G QEMU_SMP=4 ./tools/run.sh

# Запуск с аппаратным ускорением KVM на английском языке:
ENABLE_KVM=1 ./tools/run.sh en
```

## 4. Отладка и вывод последовательного порта (COM1)

Ядро Wunix инициализирует последовательный порт UART 16550 ([`kernel/src/drivers/serial.rs`](file:///home/valdis/my-os/wunix/kernel/src/drivers/serial.rs)) по базовому адресу `0x3F8` со скоростью 115200 бод.

Весь отладочный вывод макроса `serial_println!` направляется напрямую в порт COM1, который скрипт `run.sh` пробрасывает в `stdio` терминала:

```bash
# Запуск QEMU без графического окна (только serial-консоль):
./tools/run.sh -nographic
```

## 5. Стандарты качества кода (`ub-mode`)

При внесении изменений в ядро обязательно соблюдаются требования [`AGENTS.md`](file:///home/valdis/my-os/AGENTS.md):
- **Никаких монолитных свалок**: функционал изолируется по директориям в `src/arch/`, `src/drivers/`, `src/memory/`.
- **Живые комментарии**: комментарии пишутся только там, где необходимо объяснить *почему* сделано именно так (тайминги чипсета, особенности x86). Никаких шаблонных разделителей и самоочевидных комментариев.
- **Дисциплина локализации**: все сообщения, выводимые пользователю на экран, обязаны использовать подсистему `i18n`.
