Настоящий документ представляет собой официальное руководство и техническую спецификацию по добавлению поддержки новых языков в операционную систему **Wunix**.

Документ структурирован по целевым аудиториям:
- **[Раздел 1. Архитектура подсистемы локализации](#1-архитектура-подсистемы-локализации)** — общие принципы функционирования механизмов перевода в ядре.
- **[Раздел 2. Спецификация сообщений (Для переводчиков и лингвистов)](#2-спецификация-сообщений-для-переводчиков-и-лингвистов)** — перечень системных строк, контекст вывода, требования к форматированию и шаблон реестра перевода. Знание языков программирования не требуется.
- **[Раздел 3. Техническая реализация (Для разработчиков ядра)](#3-техническая-реализация-для-разработчиков-ядра)** — пошаговое руководство по модификации исходного кода на языке Rust, реализации исчерпывающего сопоставления, отрисовке растровых шрифтов 8×16 и настройке загрузчика.

## 1. Архитектура подсистемы локализации

В отличие от систем прикладного уровня, где языковые каталоги (например, файлы GNU gettext `.mo`) загружаются динамически из файловой системы, ядро Wunix функционирует в среде без стандартной библиотеки (`no_std`) и обеспечивает локализацию на этапе ранней инициализации оборудования до монтирования накопителей.

Все строковые ресурсы компилируются непосредственно в бинарный образ ядра. Локализация реализуется посредством двух взаимодополняющих механизмов:

1. **Типизированный каталог ключей (`MsgKey` и функция `tr`)**:
   Используется для основных системных сообщений ядра. Каждое сообщение идентифицируется элементом перечисления `MsgKey`. Компилятор Rust гарантирует исчерпывающее сопоставление (`exhaustive match`): отсутствие перевода для любого из ключей нового языка приводит к ошибке сборки ядра (`error[E0004]: non-exhaustive patterns`).
2. **Парный инлайн-перевод (`t(ru, en)`)**:
   Используется для компактных парных меток в форматированном выводе.

Активный язык сохраняется в атомарной переменной `AtomicU8` ([`kernel/src/i18n/mod.rs`](file:///home/valdis/my-os/wunix/kernel/src/i18n/mod.rs)), что обеспечивает потокобезопасное чтение значения без блокировок (lock-free) из любого контекста выполнения, включая обработчики аппаратных прерываний.

## 2. Спецификация сообщений (Для переводчиков и лингвистов)

Для подготовки перевода Wunix на новый язык знание программирования не требуется. Переводчику необходимо перевести строки согласно контексту и техническим ограничениям экрана, после чего передать заполненный шаблон разработчикам.

### 2.1. Реестр системных сообщений ядра

В режиме ранней инициализации вывод производится во фреймбуфер или текстовую консоль с фиксированным моноширинным знакоместом. Переполнение строк недопустимо, так как приводит к нарушению форматирования системных таблиц автоконфигурации.

| Ключ (`MsgKey`) | Исходный текст (EN) | Исходный текст (RU) | Назначение и контекст вывода | Ограничения и формат |
|---|---|---|---|---|
| `SystemReady` | `wunix: system ready` | `wunix: система готова к работе` | Уведомление об успешном завершении аппаратной инициализации подсистем ядра. | Одно предложение. Префикс `wunix: ` обязателен. Лаконичный утвердительный тон. |
| `PromptInput` | `wunix: type something on keyboard (layout switch: Alt+Shift)...` | `wunix: введите текст с клавиатуры (переключение раскладки: Alt+Shift)...` | Приглашение к пользовательскому вводу в консоли ядра с указанием сочетания клавиш переключения раскладки. | Строка, информирующая пользователя о готовности к приему ввода. |
| `InterruptCancel` | `^C (input cancelled)` | `^C (ввод отменен)` | Системный маркер при прерывании ввода комбинацией `Ctrl+C`. | Традиционный префикс `^C `, пояснение в скобках. |
| `Cpu` | `cpu` | `процессор` | Идентификатор центрального процессора в сводке обнаруженных устройств. | Одно существительное в именительном падеже, нижний регистр. |
| `Memory` | `memory` | `память` | Идентификатор оперативной памяти в сводке автоконфигурации. | Одно существительное в именительном падеже, нижний регистр. |
| `Display` | `display` | `экран` | Идентификатор видеоадаптера / фреймбуфера. | Одно существительное в именительном падеже, нижний регистр. |
| `Timer` | `timer` | `таймер` | Идентификатор системного таймера (PIT/APIC). | Одно существительное в именительном падеже, нижний регистр. |
| `Keyboard` | `keyboard` | `клавиатура` | Идентификатор контроллера ввода PS/2. | Одно существительное в именительном падеже, нижний регистр. |
| `Uptime` | `uptime` | `время работы` | Идентификатор таймера непрерывной работы ядра. | 1–2 слова в нижнем регистре. |

### 2.2. Требования к стилистике

1. **Терминологическая строгость**: Все термины должны соответствовать принятым стандартам операционных систем UNIX/POSIX.
2. **Регистр символов**: Названия компонентов оборудования (`cpu`, `память`, `таймер`) оформляются строчными буквами для сохранения табличного выравнивания. Системные статусы ядра начинаются с префикса `wunix: `.
3. **Фиксация специальных символов**: Если язык содержит диакритические знаки, умлауты или уникальные символы алфавита (например: `ä`, `ö`, `ü`, `ß`, `é`, `è`, `ç`, `ą`, `ł`), их необходимо явно указать в сопроводительном реестре. Для каждого не входящего в стандартный ASCII символа разработчикам потребуется сформировать растровую матрицу глифа в знакогенераторе.

### 2.3. Форма реестра перевода

Для передачи перевода в проект заполните следующую форму:

```text
Язык: [Название языка на русском и национальном названии, например: Немецкий / Deutsch]
Код языка (ISO 639-1): [двухбуквенный код, например: de]
Специальные символы алфавита: [перечислить все символы вне диапазона базового ASCII]

Каталог сообщений MsgKey:
- SystemReady: "..."
- PromptInput: "..."
- InterruptCancel: "..."
- Cpu: "..."
- Memory: "..."
- Display: "..."
- Timer: "..."
- Keyboard: "..."
- Uptime: "..."

Вспомогательные термины:
- Включено / Выключено: "..." / "..."
- Ошибка / Успех: "..." / "..."
```

## 3. Техническая реализация (Для разработчиков ядра)

Интеграция нового языка в кодовую базу ядра состоит из последовательного выполнения следующих шагов. В качестве эталонной реализации используется немецкий язык (**German**, код `de`).

### Шаг 1. Расширение перечисления `Language`

В файле [`kernel/src/i18n/mod.rs`](file:///home/valdis/my-os/wunix/kernel/src/i18n/mod.rs) зарегистрируйте новый вариант в перечислении `Language`:

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
#[repr(u8)]
pub enum Language {
    Russian = 0,
    English = 1,
    German = 2, // Новый язык
}
```

Атрибут `#[repr(u8)]` является обязательным, так как значение дискриминанта сохраняется непосредственно в `AtomicU8`.

Обновите логику функции получения активного языка:

```rust
pub fn current_language() -> Language {
    match CURRENT_LANGUAGE.load(Ordering::Relaxed) {
        0 => Language::Russian,
        2 => Language::German,
        _ => Language::English,
    }
}
```

---

### Шаг 2. Реализация функции сопоставления ключей `tr(key)`

В том же файле [`kernel/src/i18n/mod.rs`](file:///home/valdis/my-os/wunix/kernel/src/i18n/mod.rs) добавьте ветку для нового языка в функцию `tr()`:

```rust
pub fn tr(key: MsgKey) -> &'static str {
    match current_language() {
        Language::Russian => match key {
            MsgKey::SystemReady => "wunix: система готова к работе",
            MsgKey::PromptInput => "wunix: введите текст с клавиатуры (переключение раскладки: Alt+Shift)...",
            MsgKey::InterruptCancel => "^C (ввод отменен)",
            MsgKey::Cpu => "процессор",
            MsgKey::Memory => "память",
            MsgKey::Display => "экран",
            MsgKey::Timer => "таймер",
            MsgKey::Keyboard => "клавиатура",
            MsgKey::Uptime => "время работы",
        },
        Language::English => match key {
            MsgKey::SystemReady => "wunix: system ready",
            MsgKey::PromptInput => "wunix: type something on keyboard (layout switch: Alt+Shift)...",
            MsgKey::InterruptCancel => "^C (input cancelled)",
            MsgKey::Cpu => "cpu",
            MsgKey::Memory => "memory",
            MsgKey::Display => "display",
            MsgKey::Timer => "timer",
            MsgKey::Keyboard => "keyboard",
            MsgKey::Uptime => "uptime",
        },
        Language::German => match key {
            MsgKey::SystemReady => "wunix: System ist betriebsbereit",
            MsgKey::PromptInput => "wunix: Text eingeben (Layout wechseln: Alt+Shift)...",
            MsgKey::InterruptCancel => "^C (Eingabe abgebrochen)",
            MsgKey::Cpu => "Prozessor",
            MsgKey::Memory => "Speicher",
            MsgKey::Display => "Bildschirm",
            MsgKey::Timer => "Timer",
            MsgKey::Keyboard => "Tastatur",
            MsgKey::Uptime => "Betriebszeit",
        },
    }
}
```

> [!NOTE]
> **Контроль исчерпываемости сопоставления (Exhaustive Pattern Matching):**
> Компилятор Rust выполняет строгую проверку полноты сопоставления. Использование подстановочного шаблона `_ => ...` в теле `match key` запрещено стандартами проекта. Если при последующем развитии ядра в `MsgKey` будет добавлен новый ключ, компилятор прервет сборку с ошибкой неполного покрытия паттернов до тех пор, пока перевод не будет внесен для всех языков без исключения.

### Шаг 3. Обработка параметров командной строки ядра

Ядро Wunix принимает конфигурационные параметры при старте через интерфейс загрузчика. Для поддержки флагов вида `lang=de`, `locale=de_DE` или позиционного токена `de`, обновите функцию `init_from_cmdline` в [`kernel/src/i18n/mod.rs`](file:///home/valdis/my-os/wunix/kernel/src/i18n/mod.rs):

```rust
pub fn init_from_cmdline(cmdline: &str) {
    for token in cmdline.split_whitespace() {
        if let Some((k, v)) = token.split_once('=') {
            if k.eq_ignore_ascii_case("lang") || k.eq_ignore_ascii_case("locale") {
                match v {
                    "ru" | "RU" | "ru_RU" | "russian" => set_language(Language::Russian),
                    "en" | "EN" | "en_US" | "english" => set_language(Language::English),
                    "de" | "DE" | "de_DE" | "german"  => set_language(Language::German),
                    _ => {}
                }
            }
        } else if token.eq_ignore_ascii_case("ru") || token.eq_ignore_ascii_case("russian") {
            set_language(Language::Russian);
        } else if token.eq_ignore_ascii_case("en") || token.eq_ignore_ascii_case("english") {
            set_language(Language::English);
        } else if token.eq_ignore_ascii_case("de") || token.eq_ignore_ascii_case("german") {
            set_language(Language::German);
        }
    }
}
```

### Шаг 4. Добавление растровых глифов шрифта 8×16

Графический вывод символов осуществляется знакогенератором ядра ([`kernel/src/drivers/font.rs`](file:///home/valdis/my-os/wunix/kernel/src/drivers/font.rs)).

#### Спецификация формата растра:
- Размер знакоместа: фиксированный, 8 пикселей по ширине, 16 пикселей по высоте.
- Структура данных: массив из 16 байт (`[u8; 16]`).
- Каждый байт кодирует одну горизонтальную строку:
  - Старший бит (бит 7, `0x80`) соответствует крайнему левому пикселю.
  - Младший бит (бит 0, `0x01`) соответствует крайнему правому пикселю.
  - Значение бита `1` — пиксель цвета текста (foreground), `0` — пиксель цвета фона (background).

#### Расчет матрицы на примере символа `'ä'` (строчная а с умлаутом):

```text
Строка знакоместа     Двоичный код    Шестнадцатеричный код
Строка 0:  ........    00000000        0x00
Строка 1:  ........    00000000        0x00
Строка 2:  ..#..#..    00100100        0x24  (точки умлаута)
Строка 3:  ..#..#..    00100100        0x24
Строка 4:  ........    00000000        0x00
Строка 5:  ..####..    00111100        0x3c  (верхняя дуга)
Строка 6:  .#....#.    01000010        0x42
Строка 7:  ......#.    00000010        0x02
Строка 8:  ..#####.    00111110        0x3e
Строка 9:  .#....#.    01000010        0x42
Строка 10: .#....#.    01000010        0x42
Строка 11: ..####.#    00111101        0x3d  (хвостик буквы)
Строка 12: ........    00000000        0x00
Строка 13: ........    00000000        0x00
Строка 14: ........    00000000        0x00
Строка 15: ........    00000000        0x00
```

#### Регистрация символа в коде ядра:
В файле [`kernel/src/drivers/font.rs`](file:///home/valdis/my-os/wunix/kernel/src/drivers/font.rs):

1. Объявить константу растровой матрицы:
```rust
pub const GLYPH_A_UMLAUT: [u8; 16] = [
    0x00, 0x00, 0x24, 0x24, 0x00, 0x3c, 0x42, 0x02,
    0x3e, 0x42, 0x42, 0x3d, 0x00, 0x00, 0x00, 0x00,
];
```

2. Включить сопоставление символа в диспетчере `get_glyph(ch: char)`:
```rust
pub fn get_glyph(ch: char) -> Option<&'static [u8; 16]> {
    match ch {
        ' '..='~' => {
            let idx = (ch as u32 - 0x20) as usize;
            Some(&ASCII_GLYPHS[idx])
        }
        'А'..='я' => {
            let idx = (ch as u32 - 0x0410) as usize;
            Some(&CYRILLIC_GLYPHS[idx])
        }
        'Ё' => Some(&GLYPH_YO_UPPER),
        'ё' => Some(&GLYPH_YO_LOWER),
        '№' => Some(&GLYPH_NUMERO),
        'ä' => Some(&GLYPH_A_UMLAUT), // Добавленный символ
        _ => None,
    }
}
```

Символы, не зарегистрированные в `get_glyph`, транслируются знакогенератором в `REPLACEMENT_GLYPH` (символьную рамку знакоместа), исключая аварийный сбой рендерера.

### Шаг 7. (Опционально) Конфигурация раскладки клавиатуры

Если для целевого языка требуется национальная раскладка клавиш (например, немецкая QWERTZ или французская AZERTY):

1. В файле [`kernel/src/drivers/keyboard.rs`](file:///home/valdis/my-os/wunix/kernel/src/drivers/keyboard.rs) дополните перечисление `Layout`:
   ```rust
   pub enum Layout {
       English,
       Russian,
       German,
   }
   ```
2. Реализуйте функцию сопоставления скан-кодов PS/2 (по аналогии с `map_russian_keycode`).
3. Подключите обработку раскладки в метод диспетчера `DualLayout::map_keycode` с поддержкой циклического переключения по комбинации `Alt+Shift`.

## 4. Критерии приемки изменений

Перед объединением изменений в основную ветку репозитория необходимо убедиться в выполнении следующих требований:

- [ ] В `kernel/src/i18n/mod.rs` добавлен новый вариант перечисления `enum Language`.
- [ ] В функции `tr(MsgKey)` реализован исчерпывающий перевод всех элементов каталога `MsgKey` без использования wildcard `_ => ...`.
- [ ] В функции `init_from_cmdline` зарегистрирована обработка параметров `lang=<код>`, `locale=<код>` и короткого обозначения.
- [ ] Для всех специфических символов алфавита добавлены 16-байтовые растровые матрицы в `kernel/src/drivers/font.rs` и зарегистрированы в `get_glyph()`.
- [ ] Конфигурация `limine.conf` дополнена соответствующим пунктом меню загрузки.
- [ ] Команда `cargo check` выполняется успешно без ошибок и предупреждений компилятора.
- [ ] Сообщение коммита оформлено в соответствии со стандартом проекта: `feat(i18n): добавить поддержку немецкого языка (de)`.
