# Сетевой стек Wunix: Архитектура уровней L2–L4

Операционная система Wunix оснащена собственным сетевым стеком, разработанным на чистом Rust без привлечения тяжелых сторонних зависимостей.

---

## 1. Архитектурная модель сетевого стека

```
Приложения (curl, ping, host) / Сокеты BSD
                      │
  ┌───────────────────┴───────────────────┐
  │ L4: Транспортный уровень              │
  │     ├── TCP (Потоковые сокеты, SYN/ACK, Окно)
  │     └── UDP (Датаграммные сокеты)
  └───────────────────┬───────────────────┘
                      │
  ┌───────────────────┴───────────────────┐
  │ L3: Сетевой уровень                   │
  │     ├── IPv4 (Маршрутизация, Checksum, TTL)
  │     └── ICMP (Echo Request / Echo Reply)
  └───────────────────┬───────────────────┘
                      │
  ┌───────────────────┴───────────────────┐
  │ L2: Канальный уровень                 │
  │     ├── Ethernet II (Кадры, MAC-адресация)
  │     └── ARP (Таблица трансляции IP -> MAC)
  └───────────────────┬───────────────────┘
                      │
  ┌───────────────────┴───────────────────┐
  │ Драйвер сетевого контроллера VirtIO-Net│
  │ (Кольцевые буферы Rx/Tx Virtqueue)    │
  └───────────────────────────────────────┘
```

---

## 2. Канальный уровень: Ethernet II и ARP

### Формат кадра Ethernet II
Каждый пакет в сети оборачивается в стандартный 14-байтный заголовок:
* `Destination MAC`: 6 байт (MAC-адрес получателя или широковещательный `FF:FF:FF:FF:FF:FF`).
* `Source MAC`: 6 байт (аппаратный MAC-адрес адаптера VirtIO).
* `EtherType`: 2 байта (`0x0800` для IPv4, `0x0806` для ARP).

### Протокол разрешения адресов (ARP)
* Стек поддерживает динамическую **ARP-таблицу**: при отправке пакета на неизвестный IP-адрес ядро формирует широковещательный ARP Request (`Who has 192.168.1.1? Tell 192.168.1.50`).
* Ответы ARP Reply кэшируются с временным таймаутом устаревания для исключения лишнего широковещательного трафика.

## 3. Сетевой уровень: IPv4 и ICMP

* **IPv4 Заголовок**: 20 байт стандартного заголовка, автоматический расчет контрольной суммы заголовка (Internet Checksum, RFC 1071), проверка `TTL` (Time To Live), демультиплексирование протоколов по полю `Protocol` (`1` для ICMP, `6` для TCP, `17` для UDP).
* **ICMP**:
  * Ядро автоматически на аппаратной скорости отвечает на входящие `ICMP Echo Request` (тип 8, пинг от других машин) формированием `ICMP Echo Reply` (тип 0) с сохранением payload и идентификаторов.
  * Исходящие запросы генерируются системным вызовом сокетов `SOCK_RAW` для работы утилиты `ping`.

## 4. Транспортный уровень: UDP и TCP

### Протокол UDP (User Datagram Protocol)
Легковесный протокол без установления соединения. 8-байтный заголовок (`Source Port`, `Dest Port`, `Length`, `Checksum`). Используется DNS-клиентом (`host`) на порту 53.

### Протокол TCP (Transmission Control Protocol)
Полноценная машина состояний TCP (State Machine):
* **Установление соединения (3-way handshake)**: `CLOSED` -> `SYN_SENT` -> `ESTABLISHED`.
* **Управление окном (Sliding Window)**: отслеживание номеров последовательности `Sequence Number` и подтверждений `Ack Number`.
* **Завершение соединения**: обмен пакетами `FIN` и `ACK` с корректным переходом через состояния `FIN_WAIT_1`, `CLOSE_WAIT`, `TIME_WAIT`.

## 5. Системный интерфейс сокетов BSD

Прикладные программы взаимодействуют со стеком через стандартный POSIX-интерфейс:
* `sys_socket(domain: AF_INET, type: SOCK_STREAM | SOCK_DGRAM, proto: 0)` — создание дескриптора сокета.
* `sys_connect(fd, addr, addrlen)` — установка TCP-соединения.
* `sys_bind(fd, addr, addrlen)` — привязка серверного порта.
* `sys_listen(fd, backlog)` — перевод в режим прослушивания.
* `sys_accept(fd, addr, addrlen)` — принятие входящего соединения.
* `sys_sendto` и `sys_recvfrom` — чтение и отправка сетевых буферов.
