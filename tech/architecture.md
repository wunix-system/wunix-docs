# Низкоуровневая архитектура ядра Wunix

Ядро Wunix функционирует в 64-битном режиме **Long Mode** архитектуры x86_64 с использованием плоской модели сегментации и 4-уровневой страничной адресации.

---

## 1. Протокол загрузки и пространство Higher-Half (HHDM)

Ядро загружается с помощью протокола **Limine Boot Protocol**.  
Загрузчик подготавливает базовые таблицы страниц и отображает всю физическую память компьютера в старшую половину виртуального адресного пространства (Higher-Half Direct Map, HHDM):

* **HHDM Base**: `0xFFFF_8000_0000_0000`  
  Любой физический адрес `P` доступен ядру по виртуальному адресу `0xFFFF_8000_0000_0000 + P`.
* **Kernel Code Base**: `0xFFFF_FFFF_8000_0000` (последние 2 ГиБ адресного пространства)  
  Бинарный код и статические секции ядра (`.text`, `.rodata`, `.data`, `.bss`) линкуются в этой области.
* **Kernel Heap Base**: `0xFFFF_9000_0000_0000`  
  Область динамического выделения памяти ядра.
* **User Space Range**: `0x0000_0000_0000_0000` .. `0x0000_7FFF_FFFF_FFFF` (младшие 128 ТиБ)  
  Адресное пространство прикладных процессов Ring 3.

---

## 2. Сегментация, GDT и Task State Segment (TSS)

Несмотря на то, что в Long Mode базовая адресация является плоской (базовые адреса большинства сегментов жестко равны 0), структура **GDT (Global Descriptor Table)** необходима для задания уровней привилегий (DPL 0 vs DPL 3) и загрузки сегмента состояния задачи **TSS**.

```
Индекс GDT  Селектор  Назначение                DPL (Ring)
0           0x00      Null Descriptor           -
1           0x08      Kernel Code 64-bit        0 (Ring 0)
2           0x10      Kernel Data 64-bit        0 (Ring 0)
3           0x18      User Data 64-bit          3 (Ring 3)
4           0x20      User Code 64-bit          3 (Ring 3)
5, 6        0x28      TSS (16-байтный дескриптор) 0 (Ring 0)
```

### Interrupt Stack Table (IST)
В TSS настроен специальный аварийный стек:
* **IST1 (Double Fault Stack)**: выделенный изолированный стек размером 16 КиБ. В случае переполнения обычного стека ядра процессор генерирует исключение `#DF` (Double Fault) и гарантированно переключается на этот стек, исключая фатальный срыв в `Triple Fault`.

---

## 3. Таблица векторов прерываний (IDT)

IDT ядра содержит 256 дескрипторов шлюзов прерываний (Interrupt Gate 64-bit).

* **Векторы 0–31: Процессорные исключения Intel**:
  * `0`: `#DE` — Divide Error
  * `6`: `#UD` — Invalid Opcode
  * `8`: `#DF` — Double Fault (привязан к IST1)
  * `13`: `#GP` — General Protection Fault
  * `14`: `#PF` — Page Fault (чтение регистра `CR2` для получения адреса сбоя)
* **Векторы 32–47: Аппаратные прерывания IRQ (PIC 8259 Remap)**:
  * Векторы 8–15 реального режима BIOS перемаппированы на 32–47 во избежание конфликта с исключениями CPU:
  * `32 (IRQ 0)`: Таймер PIT 8254 (1000 Гц)
  * `33 (IRQ 1)`: Клавиатура PS/2 (скан-коды)
  * `36 (IRQ 4)`: COM1 последовательный порт (UART 16550)
  * `42 (IRQ 10)`: Прерывания VirtIO PCI устройств
  * `43 (IRQ 11)`: VirtIO Net адаптер

---

## 4. Быстрый переход в Ring 3: MSR LSTAR и инструкция `syscall`

Для минимизации накладных расходов при вызове системных функций Wunix не использует медленные шлюзы прерываний `int 0x80`. Вместо этого задействован механизм аппаратных инструкций **`syscall`** / **`sysretq`**:

1. При старте ядро инициализирует системные регистры MSR (Model Specific Registers):
   * **`IA32_LSTAR` (`0xC0000082`)**: адрес ассемблерной точки входа `syscall_entry`.
   * **`IA32_STAR` (`0xC0000081`)**: селекторы сегментов GDT для Ring 0 и Ring 3.
   * **`IA32_FMASK` (`0xC0000084`)**: битовая маска сброса флагов RFLAGS при входе (сбрасываются `IF` прерывания, `DF` направление, `TF` отладка).
2. При выполнении инструкции `syscall` в Ring 3:
   * Процессор сохраняет `RIP` в регистр `RCX`.
   * Процессор сохраняет `RFLAGS` в регистр `R11`.
   * Аппаратно переключается в Ring 0 и переходит на `IA32_LSTAR`.
3. В точке входа `syscall_entry`:
   * Сохраняется стек пользователя `RSP` и восстанавливается стек ядра из структуры текущего потока.
   * Регистры аргументов `RDI`, `RSI`, `RDX`, `R10`, `R8`, `R9` передаются в диспетчер `syscall_dispatcher`.
   * Результат возвращается в `RAX`.
   * Инструкция `sysretq` мгновенно возвращает выполнение в Ring 3.
