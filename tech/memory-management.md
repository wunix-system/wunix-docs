# Управление памятью: физический и виртуальный менеджеры

Подсистема памяти ядра Wunix управляет физической RAM компьютера, динамической виртуальной адресацией и изоляцией пространств процессов.

---

## 1. Физический менеджер памяти (Bitmap Frame Allocator)

Физическая память разбита на базовые страницы размером 4096 байт (**4KiB фреймы**).

* **Карта памяти Limine**: Загрузчик передает ядру массив областей физической памяти (`LimineMemoryMapEntry`). Ядро фильтрует области с типом `USABLE` (доступная оперативная память) и исключает зарезервированные области BIOS, ACPI NVS и Framebuffer.
* **Битовая карта (Bitmap)**: Состояние каждого физического фрейма кодируется одним битом:
  * `0` — фрейм свободен.
  * `1` — фрейм занят ядром или пользовательским процессом.
* **Аллокация и освобождение**:
  * `alloc_frame() -> Option<PhysFrame>` — находит первый свободный бит за время $O(1)$ благодаря битовым операциям поиска первого нуля (`trailing_ones` / `leading_zeros`), помечает его единицей и возвращает физический адрес фрейма.
  * `free_frame(frame: PhysFrame)` — сбрасывает соответствующий бит в `0`.

## 2. Виртуальная память и 4-уровневые таблицы страниц

Архитектура x86_64 в 64-битном режиме использует 48-битную виртуальную адресацию через 4 уровня таблиц:

```
Виртуальный адрес (48 бит):
47        39 38       30 29       21 20       12 11          0
┌───────────┬───────────┬───────────┬───────────┬────────────┐
│ PML4 (9b) │ PDPT (9b) │  PD (9b)  │  PT (9b)  │ Offset(12b)│
└───────────┴───────────┴───────────┴───────────┴────────────┘
     │           │           │           │            │
     ▼           ▼           ▼           ▼            ▼
CR3 ──► PML4 ──────► PDPT ──────► PD ────────► PT ─────► [4KiB Физический фрейм]
```

### Флаги записей страниц (Page Table Entry Flags):
* `PRESENT (бит 0)`: Страница присутствует в физической памяти. Если бит сброшен, обращение вызывает `#PF` (Page Fault).
* `WRITABLE (бит 1)`: Разрешена запись в страницу (если сброшен — только чтение).
* `USER_ACCESSIBLE (бит 2)`: Разрешен доступ из Ring 3 (если сброшен — доступ только из Ring 0).
* `WRITE_THROUGH (бит 3)`: Сквозная запись в кэш CPU.
* `NO_CACHE (бит 4)`: Запрет кэширования (используется для видеопамяти MMIO и регистров устройств).
* `ACCESSED (бит 5)`: Устанавливается процессором при любом чтении страницы.
* `DIRTY (бит 6)`: Устанавливается процессором при записи в страницу.
* `NO_EXECUTE (бит 63)`: Защита от исполнения кода (NX/XD бит). Попытка выполнить инструкцию из страницы данных немедленно вызывает исключение `#PF`.

## 3. Куча ядра (Kernel Heap)

Для поддержки динамических структур языка Rust (`Box`, `Vec`, `String`, `Arc`, `BTreeMap`) ядро реализует глобальный аллокатор памяти `#[global_allocator]`:

* Базовый адрес кучи ядра: `0xFFFF_9000_0000_0000`.
* При старте под кучу выделяется пул страниц размером 1 МиБ.
* Аллокатор использует связанный список свободных блоков (**Linked List Allocator**) с объединением смежных фрагментов при освобождении памяти для предотвращения фрагментации.
* При исчерпании пула куча динамически запрашивает новые 4KiB фреймы у физического аллокатора и расширяет верхнюю границу диапазона виртуальной памяти.
