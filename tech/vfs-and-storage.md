# Виртуальная файловая система (VFS) и гибридное хранилище

Подсистема виртуальной файловой системы (**VFS**) операционной системы Wunix реализует гибридную монолитную архитектуру: в рамках единого корневого пространства имен (`/`) параллельно сосуществуют классическая иерархия стандартов **POSIX/UNIX** и изолированное поддерево подсистемы **Windows NT**.

```
/ (Единый корень VFS)
├── bin, sbin, etc, dev, proc, sys, tmp    # Классическая иерархия UNIX
├── home/user                              # Канонический профиль пользователя
└── win/                                   # Пространство подсистемы Windows NT
    ├── drives/
    │   └── c/                             # Проекция диска C:\
    │       ├── Program Files/
    │       ├── Users/user ───────────────► [Символическая ссылка на /home/user]
    │       └── Windows/System32/
    └── registry/                          # Ульи реестра (system.reg)
```

---

## 1. Механизм трансляции путей (`fs/path.rs`)

Ядро прозрачно поддерживает как пути UNIX, так и синтаксис путей Windows:

* **Проекция дисков Windows**: пути вида `C:\Windows\...` или `c:/windows/...` на уровне ядра нормализуются в канонический вид `/win/drives/c/Windows/...`. Буква диска всегда приводится к нижнему регистру.
* **Нормализация разделителей**: обратные слеши `\` прозрачно конвертируются в прямые `/`.
* **Схлопывание относительных переходов**: компоненты `.` и `..` вычисляются через стек директорий без возможности выхода выше корня `/`.
* **Регистронезависимый поиск (Case-Insensitive)**: для поддерева `/win/...` операции поиска узлов (`lookup`) выполняются без учета регистра символов ASCII (поведение NT Object Manager / Win32). При поиске `c:\windows\system32` ядро корректно находит `Windows/System32`.
* **Единый профиль пользователя**: для исключения дублирования документов и настроек между средами Unix и Windows создается символическая ссылка:
  ```
  /win/drives/c/Users/user  ───(Symlink)───►  /home/user
  ```

## 2. Модульные типажи VFS (`fs/vfs.rs`)

VFS абстрагирует конкретные файловые системы через полиморфные трейты Rust:

### Трейт `Inode: Send + Sync`
Каждый узел дерева (файл, каталог, символическая ссылка, символьное/блочное устройство) реализует интерфейс `Inode`:
* `read_at(&self, offset: u64, buf: &mut [u8]) -> Result<usize, VfsError>`
* `write_at(&self, offset: u64, buf: &[u8]) -> Result<usize, VfsError>`
* `lookup(&self, name: &str) -> Result<Arc<dyn Inode>, VfsError>`
* `create(&self, name: &str, inode_type: InodeType, mode: u32) -> Result<Arc<dyn Inode>, VfsError>`
* `readdir(&self, offset: usize) -> Result<Option<DirEntry>, VfsError>`
* `read_link(&self) -> Result<String, VfsError>`
* `stat(&self) -> Result<Stat, VfsError>`
* `sync(&self) -> Result<(), VfsError>`

### Трейт `FileSystem: Send + Sync`
Интерфейс монтируемой файловой системы:
* `root(&self) -> Arc<dyn Inode>` — возвращает корневой узел файловой системы.
* `name(&self) -> &'static str` — текстовый идентификатор (`ramfs`, `vfat`, `procfs`).

## 3. Реализованные файловые системы

### 1. `ramfs` и `tar` (Initramfs)
Корневая файловая система разворачивается в оперативной памяти из архива `initramfs.tar`.
* Парсер `tar.rs` декодирует стандартные 512-байтные заголовки USTAR во время загрузки ядра.
* Создает узлы `RamfsDir` и `RamfsFile` в памяти Higher-Half.
* Поддерживает запись и динамическое расширение файлов в оперативной памяти.

### 2. `fat` (Драйвер FAT16/FAT32)
Полноценный драйвер постоянных накопителей с поддержкой жестких дисков и VirtIO-Block:
* **BIOS Parameter Block (BPB)**: чтение геометрии сектора, зарезервированных секторов, размера кластера и количества таблиц FAT.
* **Cluster Chains**: трассировка цепочек кластеров в таблице FAT32 для непрерывного и фрагментированного чтения/записи.
* **Long File Names (LFN)**: поддержка длинных имен файлов в кодировке UTF-16, сборка составных LFN-записей перед 8.3 Short Name.

### 3. `procfs` и `sysfs`
Псевдофайловые системы ядра, генерирующие текстовые данные «на лету» без обращения к дискам:
* `/proc/meminfo` — статистика физических страниц Frame Allocator.
* `/proc/cpuinfo` — характеристики ядер x86_64 из инструкций CPUID.
* `/proc/uptime` — аптайм ядра по тикам системного таймера PIT/APIC.
* `/proc/net/dev` — счетчики переданных и принятых пакетов интерфейса VirtIO-Net.
* `/proc/<pid>/status` — состояние потока, PID, виртуальная память и дескрипторы.
* `/sys/bus/pci/devices` — топология обнаруженных устройств шины PCI.
