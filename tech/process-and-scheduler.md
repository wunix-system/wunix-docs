# Управление процессами, планировщик и Ring 3

Подсистема управления задачами ядра Wunix обеспечивает вытесняющую многозадачность, изолированные адресные пространства для процессов пользователя и загрузку исполняемых бинарников ELF64.

---

## 1. Блок управления задачей (Task Control Block, TCB)

Каждый поток в ядре представляется структурой `Thread`:

```rust
pub struct Thread {
    pub id: ThreadId,                 // Уникальный идентификатор потока (TID)
    pub process_id: ProcessId,       // Идентификатор группы процессов (PID / TGID)
    pub state: Mutex<ThreadState>,   // Состояние: Ready, Running, Blocked, Zombie
    pub context: Mutex<CpuContext>,  // Сохраненный контекст регистров CPU
    pub page_table: Arc<PageTable>,  // PML4 таблица виртуальной памяти процесса
    pub fd_table: Arc<Mutex<FdTable>>,// Таблица открытых файловых дескрипторов
    pub user_stack_top: u64,         // Вершина стека пользователя Ring 3
    pub kernel_stack_top: u64,       // Вершина стека ядра Ring 0 при прерывании
    pub fs_base: u64,                // Базовый адрес TLS регистра FS_BASE
    pub uid: u32,                    // User ID процесса
    pub gid: u32,                    // Group ID процесса
}
```

---

## 2. Планировщик потоков (Round-Robin Scheduler)

Планировщик ядра функционирует по алгоритму **Round-Robin** с квантом времени 50 миллисекунд:

* Очередь готовых к исполнению потоков `run_queue: VecDeque<Arc<Thread>>` защищена спинлоком `Spinlock`.
* При каждом тике таймера PIT (1000 Гц) уменьшается счетчик оставшегося времени текущего потока.
* По истечении кванта (50 тиков) обработчик прерывания таймера вызывает функцию `schedule()`:
  1. Текущий поток помещается в конец очереди `run_queue`.
  2. Из начала очереди извлекается следующий готовый поток в состоянии `Ready`.
  3. Вызывается низкоуровневая ассемблерная функция переключения контекста `context_switch`.

---

## 3. Переключение контекста (`context_switch`)

Ассемблерная процедура `context_switch(old_rsp: *mut u64, new_rsp: u64, new_cr3: u64)`:

1. Сохраняет callee-saved регистры архитектуры x86_64 (`RBX`, `RBP`, `R12`, `R13`, `R14`, `R15`) на стеке текущего потока.
2. Сохраняет текущий указатель стека `RSP` в поле `old_rsp`.
3. Загружает новый указатель стека `RSP` из `new_rsp`.
4. Если `new_cr3` отличается от текущего `CR3`, процессор перезагружает регистр `CR3`, мгновенно переключая виртуальное адресное пространство на таблицы страниц нового процесса с инвалидацией неглобальных записей TLB.
5. Восстанавливает регистры `R15`–`R12`, `RBP`, `RBX` нового потока.
6. Инструкция `ret` передает управление по адресу возврата нового потока.

## 4. Загрузчик бинарников ELF64 (`task/elf.rs`)

При системном вызове `sys_execve`:
1. Ядро открывает бинарник и считывает 64-байтный ELF Header (`e_ident`: `0x7F 'E' 'L' 'F'`, 64-bit, Little Endian, x86_64).
2. Создается новое пустое адресное пространство `PageTable` (PML4). В него зеркалируются все верхние 256 записей ядра (Higher-Half Direct Map и код ядра).
3. Парсятся Program Headers: для каждого сегмента с типом `PT_LOAD`:
   * Выделяются физические 4KiB фреймы.
   * Страницы маппируются по виртуальным адресам `p_vaddr` с флагами `p_flags` (`PF_R`, `PF_W`, `PF_X`).
   * Данные из файла копируются в выделенные страницы, остаток до `p_memsz` заполняется нулями (`.bss`).
4. Выделяется стек пользователя Ring 3 (по умолчанию 2 МиБ, растущий вниз от `0x0000_7FFF_FFFF_0000`).
5. На вершине стека формируется стандартный блок инициализации Linux ABI:
   * Массив аргументов `argv` и счетчик `argc`.
   * Массив переменных окружения `envp`.
   * Вектор вспомогательных записей `auxv` (Auxiliary Vector: `AT_PHDR`, `AT_PHENT`, `AT_PHNUM`, `AT_PAGESZ`, `AT_ENTRY`, `AT_UID`, `AT_EUID`).
6. Указатель инструкции `RIP` устанавливается на точку входа `e_entry`, и процесс стартует в Ring 3.
