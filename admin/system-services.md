# Инициализация, службы и управление системой

В этом разделе описана архитектура пространства пользователя Wunix, процесс инициализации ядра `init` (PID 1), менеджер и супервизор служб `system`, настройка системных часов и управление питанием.

---

## 1. Процесс инициализации `init` (PID 1)

После завершения базовой инициализации оборудования, страничной памяти и VFS ядро передает управление первому процессу пространства пользователя (Ring 3): **`/bin/init`** (PID 1).

### Обязанности процесса `init`:
1. **Монтирование обязательных псевдофайловых систем**:
   * `/dev` — виртуальные символьные устройства (консоли, `/dev/null`, `/dev/zero`).
   * `/proc` — динамическая статистика ядра, памяти и процессов.
   * `/sys` — топология оборудования и устройств шины PCI.
   * `/tmp` — разделяемая память ramfs для временных файлов.
2. **Монтирование постоянных разделов**:
   * Обработка таблицы `/etc/fstab` и монтирование постоянных накопителей FAT32.
3. **Автозапуск системных служб**:
   * Сканирование каталога `/etc/services/enabled/` и запуск сконфигурированных демонов (сетевой стек, фоновая синхронизация времени `timesyncd`, SSH-сервер).
4. **Запуск терминальных консолей**:
   * Запуск менеджера авторизации `login` на виртуальных консолях (`tty1`–`tty4`).
5. **Супервизия процессов**:
   * Перехват и очистка процессов-сирот (orphan processes) через системный вызов `wait4`.

## 2. Менеджер служб и демонов: `system`

Для управления фоновыми службами, демонами и автозапуском в Wunix используется утилита **`system`**. Она предоставляет прозрачный, надежный интерфейс управления жизненным циклом процессов, ведения журналов и редактирования конфигураций.

### Основной синтаксис
```bash
system <КОМАНДА> [ПАРАМЕТРЫ]...
```

---

### Команды управления жизненным циклом

#### 1. Запуск, остановка и перезапуск
* **`system start <служба>`**  
  Запускает службу в фоновом режиме. Менеджер считывает конфигурационный файл `/etc/services/<служба>.conf`, порождает дочерний процесс (`fork`/`execve`), сохраняет его PID в `/var/run/services/<служба>.pid` и перенаправляет потоки вывода в журнал `/var/log/services/<служба>.log`.
  ```bash
  sudo system start timesyncd
  ```

* **`system stop <служба>`**  
  Корректно останавливает запущенную службу, считывая ее PID из `/var/run/services/<служба>.pid` и отправляя сигнал завершения `SIGTERM` (при необходимости — `SIGKILL`).
  ```bash
  sudo system stop timesyncd
  ```

* **`system restart <служба>`**  
  Последовательно останавливает службу и инициирует её повторный запуск с перечитыванием файла конфигурации.
  ```bash
  sudo system restart timesyncd
  ```

---

### Мониторинг и диагностика

#### 2. Статус служб: `system status` и `system list`
* **`system status <служба>`**  
  Выводит подробную информацию о состоянии конкретной службы:
  * Текущий статус (активна / остановлена / сбой);
  * Идентификатор процесса (PID);
  * Время непрерывной работы (uptime);
  * Статус автозапуска при старте ОС (enabled / disabled);
  * Последние строки из журнала вывода службы.
  ```bash
  system status timesyncd
  ```

* **`system list`** (или `system status` без аргументов)  
  Выводит сводную цветную таблицу всех зарегистрированных в системе служб, их описание, текущее состояние и статус автозапуска:
  ```bash
  system list
  ```

---

### Просмотр журналов: `system logs`

Все потоки стандартного вывода (stdout) и ошибок (stderr) каждой службы автоматически изолируются и записываются ядром в отдельный файл журнала:
`/var/log/services/<служба>.log`

Команда `system logs` предоставляет удобный интерфейс для их анализа:

* **Просмотр последних строк журнала** (по умолчанию 20 строк):
  ```bash
  system logs timesyncd
  ```

* **Указание точного количества строк** (`-n`, `--lines`):
  ```bash
  system logs timesyncd -n 50
  ```

* **Просмотр первых строк журнала** (`--head`):
  ```bash
  system logs timesyncd --head 15
  ```

* **Непрерывное отслеживание вывода в реальном времени** (`-f`, `--follow`):
  ```bash
  system logs timesyncd -f
  ```

---

### Создание и редактирование служб: `system create` и `system edit`

#### `system create <служба>` — создание новой службы
Автоматически генерирует файл конфигурации `/etc/services/<служба>.conf` с понятным комментированным шаблоном параметров и сразу открывает его во встроенном текстовом редакторе `nano`:
```bash
sudo system create mydaemon
```

#### `system edit <служба>` — редактирование существующей службы
Открывает файл конфигурации указанной службы в редакторе `nano`. После сохранения файла и выхода из редактора можно применить изменения командой `system restart <служба>`:
```bash
sudo system edit timesyncd
```

---

### Управление автозагрузкой: `system enable` и `system disable`

* **`system enable <служба>`**  
  Включает автоматический старт службы при загрузке операционной системы. Создает символическую ссылку в специальном каталоге:
  ```
  /etc/services/enabled/<служба>.conf ──(symlink)──► /etc/services/<служба>.conf
  ```
  ```bash
  sudo system enable sshd
  ```

* **`system disable <служба>`**  
  Отключает службу из автозагрузки, безопасно удаляя символическую ссылку из каталога `/etc/services/enabled/`. Файл конфигурации в `/etc/services/` при этом полностью сохраняется.
  ```bash
  sudo system disable sshd
  ```

---

### Формат файла конфигурации службы (`/etc/services/<имя>.conf`)

Файлы конфигураций используют интуитивно понятный синтаксис пар `ключ = значение`:

```ini
# Описание назначения службы (отображается в system list и system status)
description = Демон синхронизации системного времени Wunix

# Полный путь к исполняемому файлу и обязательные аргументы запуска
command = /bin/timesyncd -1

# Автоматический запуск при старте ОС (yes / no)
autostart = yes

# Политика перезапуска при падении (always / on-failure / no)
restart = on-failure

# Пользователь, от имени которого исполняется служба (root или имя учетной записи)
user = root

# Рабочая директория процесса
directory = /
```

## 3. Системное время и аппаратные часы (`timedatectl` и `hwclock`)

В Wunix учет времени разделен на два уровня:
1. **Системные часы ядра (System Time)**: монотонный счетчик времени ядра с момента эпохи Unix (1 января 1970 г.).
2. **Аппаратные часы CMOS RTC**: микросхема MC146818 на материнской плате с независимым батарейным питанием.

### `timedatectl` — системное время и таймзоны
* Просмотр текущего времени, статуса синхронизации и часового пояса:
  ```bash
  timedatectl status
  ```
* Ручная установка системного времени:
  ```bash
  sudo timedatectl set-time "2026-11-03 12:00:00"
  ```

### `hwclock` — синхронизация с микросхемой CMOS
* Чтение аппаратного времени из CMOS:
  ```bash
  sudo hwclock
  ```
* Запись системного времени ядра в микросхему RTC:
  ```bash
  sudo hwclock --systohc
  ```
* Установка системного времени из микросхемы RTC:
  ```bash
  sudo hwclock --hctosys
  ```

## 4. Завершение работы и перезагрузка

Операции выключения и перезагрузки требуют привилегий суперпользователя (`root` или `sudo`).

### `shutdown` — безопасный останов ОС
Команда `shutdown` выполняет корректную остановку всех запущенных служб, принудительно синхронизирует и сбрасывает дисковый кэш на накопители (`sync`), безопасно отмонтирует файловые системы и отключает питание через интерфейсы ACPI / QEMU:
```bash
sudo shutdown -h now
```

### `reboot` — быстрая перезагрузка
Перезагружает систему через аппаратный контроллер клавиатуры 8042 или тройное процессорное исключение:
```bash
sudo reboot
```
